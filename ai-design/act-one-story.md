# 第一幕逐屏脚本：让电脑做出一次预测

状态：本轮脚本已实现到第一幕预览。入口为同目录的 `index.html`，可编辑源为 `minimal-learning-scene.html`。

## 这一幕要讲通什么

这一幕的目标是让用户理解：我们希望电脑根据已有记录，估计一个还不知道的结果。为此，需要一条能接受输入、计算预测的规则；可以先用已知答案检查它，再把它用于未知情况。

小车只负责把这件事变得可见：时间是输入，位置是结果。文案围绕已有记录、预测规则、新结果和验证展开。运动条件、刻度安排、数值生成等细节放在实现约定里，仅在理解当前操作确实需要时说明。

本幕只开放一个调整量，让用户看到一次改动如何同时改变多个预测。取消代码屏与代码入口。

## 屏幕约定

- 一块连续的讲解文字，位于固定区域。目的、操作说明和反馈在这里替换。
- 纯文字屏不显示轨道、输入框或计算图。
- 互动屏只有一条轨道和当前任务需要的操作。尺寸、颜色沿用已认可的极简设计。
- 不设大标题、副标题、课程进度条、独立图例、常驻提示或“教学样本”页脚。本文标题仅用于脚本文档。
- 上一页、下一步保留在同一位置。操作引起的变化发生在原场景中。
- 本文每屏的主按钮复用这一处导航位置，不额外复制一套操作区。
- 文案里的数值从当前状态计算。以下大括号内容都是动态值。

## 01｜先知道要做什么

**形式：纯文字。**

> 我们想让电脑做到一件事：根据已有的记录，预测一个还不知道的结果。
>
> 先从一个简单例子开始。这里有小车前几秒的位置记录，我们想让电脑算出它下一秒会在哪里。
>
> 下一秒的结果先不揭开。我们先看看，电脑可以依据什么来预测。

继续按钮：`看看已有的记录 →`

这一屏先讲预测目的，再引入承载它的例子。暂时不出现训练、参数、预测线等词。

## 02｜已有记录能告诉我们什么

**形式：轨道上直接显示已有记录。**

主文字：

> 这些实心标记是已经知道的位置。它们给了我们几组“时间—位置”的对应关系。
>
> 但记住这些答案还不够：我们要预测的下一秒，并不在这些记录里。

轨道直接显示第0至3秒的记录，保留时间标记、少量位置刻度与厘米单位。来源在这一屏主文字末尾用一句话交代：`这里使用一组简单的模拟记录。`

继续按钮：`怎样从记录走向预测？ →`

删除逐秒播放、反复报告运动距离的步骤。这里需要理解的是“我们已经知道哪些答案，还不知道哪个答案”，而不是学习怎样观察小车运动。

## 03｜为什么要有一条规则

**形式：纯文字。**

> 我们需要一条规则：给它一个时间，它就能算出一个预测位置。
>
> 规则一开始可能不准。好在，前面的记录有已知答案，可以先用来检查和调整它。
>
> 接下来，空心标记表示规则算出的预测。让它们靠近实心记录，是为了找到一条更符合已有记录的规则。

继续按钮：`试着对上这些记录 →`

这里说明调整的目的：用已有答案检查预测规则。主文字区同时解释标记含义，不额外生成图例。

## 04｜让规则回应你的调整

**形式：原轨道，预测小车与记录对照。**

初始规则：起点20厘米，每秒前进20厘米。

初始文案：

> 当前规则在第3秒预测出80厘米，而记录是110厘米。我们先调整规则，让它更接近已知答案。
>
> 拖动第3秒的空心标记。它会改变规则里的“每秒前进多少厘米”，前两秒的预测也会一起重算。

轨道保留第0至3秒的实心记录。第3秒的空心小车是唯一拖动手柄；第1、2秒的预测用轻量空心标记表示。触控与键盘均能调整。

拖动时，界面把手柄对应的位置换算为“每秒前进的距离”，然后重新计算所有预测位置。不能只移动一个图形而不改变规则。

操作后的第二段被以下反馈替换：

- 尚有差距：`第3秒的预测现在是{p3}厘米，与记录相差{abs(p3−110)}厘米。你调整的是同一条规则，所以其他时刻的预测也跟着改变。`
- 对齐到显示精度：`现在，同一条规则算出的三个预测都与记录对上了。接下来，用它预测一个还没看过的结果。`
- 调到边界：`已到这次实验的调整范围。第3秒的预测是{p3}厘米，与记录相差{abs(p3−110)}厘米。` 同一段说明，不弹窗。

反馈每次都按当前数值生成。只有三条记录都符合显示精度时，才能写“都对上了”。

继续按钮：`把这条规则用到第4秒 →`

不强制用户完美对齐后才能继续。保留有偏差的规则也有教学价值，下一屏将说明它的实际后果。

## 05｜预测一个还没展示的结果

**形式：同一轨道，时间来到第4秒。**

进入时冻结本次规则和预测，不展示第4秒的模拟结果。

主文字：

> 现在，把还没有答案的第4秒交给同一条规则。它算出的预测是{p4}厘米。
>
> 这就是我们想做的：根据已有记录，给出一个未知结果的估计。接下来再揭开结果，检查这次预测。

空心小车放在预测位置。第0至3秒的记录保留，第4秒的实心小车暂不出现。

操作：`揭开结果，检查预测`。

点击后使用同一个模拟计算第4秒的真实位置140厘米，再显示实心小车。不得用预测位置代替模拟结果，也不得自动修正规则。

主文字原位替换：

- 有偏差：`揭开的结果是140厘米，预测是{p4}厘米，相差{abs(p4−140)}厘米。规则给出了一个新预测，但预测仍可能有偏差。`
- 对齐到显示精度：`揭开的结果也是140厘米。这次，我们用已有记录调整的规则，预测对了一个没有参与调整的结果。`

反馈之后在同一文字区补一句：`一次对上，还不能保证它在其他情况下也都准确。`

反馈后再出现：`拆开这次计算 →`。

这一屏的操作有明确用途：把事先给出的预测与独立的模拟结果比较。不是让用户猜选项，也不把“算出了一个数字”当作“已经正确”。

## 06｜预测不是凭空出现的

**形式：原场景内显示一次真实计算。**

主文字：

> 电脑并没有提前看到刚才揭开的答案。它只是把新的时间，放进我们调整过的规则。
>
> 这次的计算是：20 + 4 × {v} = {p4} 厘米。

原预测位置保留，主文字区展示当前数值。用一句话对应数字：`20是已知的起点，4是新输入的时间，{v}是刚才调整的每秒距离，{p4}是算出的预测。`

点击输入、可调整的数或输出时，强调对应的时间标记、规则数值或预测位置。没有新问题需要探索时，不强加额外操作。

取消走四步、反复累加和运动公式推演。这一屏要追踪的是“输入经过规则得到预测”，而不是完整讲授匀速运动。

继续按钮：`这算是机器学会了吗？ →`

## 07｜说清我们已经做到哪里

**形式：纯文字。**

> 我们已经做成了一件事：用已有记录调整一条规则，再把新的输入交给它，得到一个预测。这样一条用来预测的规则，就是一个简单的模型。
>
> 刚才是你在检查记录、调整规则。电脑已经能计算预测，还需要学会怎样自己改进。
>
> 下一步，要让机器判断一次调整有没有变好，再自己继续调整。

主继续按钮：`下一幕：让机器自己调整 →`

该按钮现已接入第二幕。第二幕另开一次实验，第一幕的规则与已揭开的结果保持原状态，返回时继续使用。

## 数值与状态约定

以下是实现约定，不作为常驻说明展示给用户。

| 项目 | 约定 |
| --- | --- |
| 模拟条件 | 直线匀速，不加入加速、随机抖动或测量噪声 |
| 模拟实际位置 | `actual_position(t) = 20 + 30 × t`，单位厘米 |
| 已展示记录 | 第0、1、2、3秒，对应20、50、80、110厘米 |
| 待验证结果 | 第4秒，140厘米；在预测前不展示 |
| 预测规则 | `prediction(t) = 20 + v × t` |
| 初始可调值 | `v = 20`，单位厘米/秒 |
| 调整范围 | `5 ≤ v ≤ 40`，对应第3秒预测位置35至140厘米 |
| 拖动换算 | `v = (拖动位置 − 20) / 3`，再限制到本次范围 |
| 键盘操作 | 第3秒预测小车获得焦点后，用左右方向键改变 `v`，每次1厘米/秒 |
| 第4秒预测范围 | 40至180厘米；轨道需完整容纳记录、预测和手柄 |
| 显示精度 | 位置与距离保留一位小数，需要时省略末尾的0；内部保留完整精度 |
| 对齐文案 | 以各条记录的显示值逐一比较；不依据手柄距离或预设成功状态 |
| 数据来源 | 模拟数据，展示已有记录时已说明；不声称来自现实测量 |

实际模拟与预测规则分别存储：调整 `v` 只改变预测，不改变记录。实际模拟的速度不直接写入预测规则。

所有场景共享当前 `v`。返回前页保留记录与调整；若返回第04屏再次改变 `v`，必须清除旧的第4秒预测快照和验证状态，再计算并核对新的预测。用户已经看过答案的事实不会重置，文案也不能再次称其为未知结果。不能让新的规则搭配旧的反馈。

运动过程可由同一位置函数实时插值绘制；减少动态效果时，直接跳到计算后的准确位置。动画只呈现计算结果，不充当算法本身。

## 这一轮暂时放下什么

不引入代码、损失、导数、学习率、神经网络、语言模型结构，不提供多个参数或自由输入时间的实验台。下一幕围绕“怎样让预测更准”，让用户看到某次调整使偏差变小，再建立衡量多个偏差的方法。是否沿用小车，取决于它能否直接支持这个问题。

后续第二个验证片段才切换到“同一个词遇到不同上下文”，检验极简舞台如何承载另一种计算，而不是把它硬塞进轨道或曲线。

## 实现前的验收问题

1. 用户看完开场，能说出目标是根据已有记录预测一个未知结果吗？
2. 第一次拖动前，他知道哪个对象代表记录、哪个代表预测，以及拖动会改变什么吗？
3. 改动之后，第1、2、3、4秒的位置是否都来自同一条当前规则？
4. 没调准也继续时，后续是否展示真实偏差，而不是统一的成功文案？
5. 第4秒的实际模拟结果是否与预测独立计算？
6. 用户能指出哪一个数是输入、规则里的哪个数被调整，以及预测结果怎样算出吗？
7. 结束时，他能分清“规则计算了结果”和“机器自己改善了规则”吗？

第一幕预览已实现。`verify-scene.mjs` 已核对不同容器宽度下的计算、拖动换算、键盘调整、预测快照、结果核对、返回重试和公式关联。此检查使用模拟页面元素，不代表实际浏览器排版或用户理解已经通过验证；这些验收问题仍需在真实体验中核对。
